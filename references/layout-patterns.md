# 任务型页面的布局与状态模式

这些是实现和复核时需要落到代码里的规则。根据真实内容选择尺寸；示意值不是产品验收标准。保留字段、文案、功能和原有品牌。每种布局都要看长文本、错误状态与手机。

## 浏览工具先呈现可用内容

查找素材、预约或记录的页面，首屏应能开始比较真实条目。首页的标题、搜索、类别标签、分类卡片和导航菜单常常重复承担导览，叠加后把真正内容推到很远。保留各入口和信息，但调整组织：主搜索清楚，当前类别/条件明确，完整分类可通过明确命名的展开区或选择器查看；避免在手机首屏同时展开多份完整目录。宣传内容与检索任务分开安排，不能只缩小所有文字。

默认折叠筛选时，显示当前条件和显眼的展开入口；有条件时不能只显示“筛选”两字。展开后按完整标签与选项长度安排，长选择值有全文补充或足够空间。查看原始/筛选/无结果三种状态，不能只看默认“全部”。

## 卡片的识别区与短动作同排

条目名称、属性和收藏等短动作属于同一识别区。若文字可完整辨认，把短动作放在文字组旁，避免为一个小按钮单独增加一整行空白。示意结构：

```css
.item-footer {
  display: grid;
  grid-template-columns: minmax(0, 1fr) auto;
  align-items: center;
  gap: .75rem;
}
.item-identity { min-width: 0; }
.item-action { min-height: 2.75rem; }
```

名称较长或窄屏不足时允许动作换行；不能以无入口的截断换取紧凑。保持文字动作与触点清楚，不遮挡图片；收藏状态发生变化时布局不应跳动。检查实际图像、文字与空白的比例，既不要让巨图推远身份信息，也不要让空白操作区和过小缩略图占据卡片。

## 宽屏短字段需要比较两列与三列

不要机械沿用框架默认的两列或让所有字段全宽。对宽屏业务表单，先按填写顺序分组，再检查每组字段所需宽度。多个短选择/短文本字段在约千像素内容区常可清楚地排成三列；只有实测长值需要时才减少列数。对当前两列方案，实际试一版三列，在相同视口比较能否更早看到下一组，而不是只凭“更宽松”决定。

一个可调整的起点：

```css
.form-section { container-type: inline-size; }
.field-grid {
  display: grid;
  grid-template-columns: 1fr;
  gap: 1rem 1.25rem;
  align-items: start;
}
@container (min-width: 34rem) {
  .field-grid { grid-template-columns: repeat(2, minmax(0, 1fr)); }
}
@container (min-width: 56rem) {
  .field-grid { grid-template-columns: repeat(3, minmax(0, 1fr)); }
  .field-wide { grid-column: span 2; }
}
```

长用途或描述可以跨列，相关的短联系字段仍可占一列。宽屏中合理并排，小屏按 DOM 填写顺序重排；不要靠 CSS order 使视觉和键盘顺序冲突。手机起止日期、开始时间/时长等关联短字段也可成对并排，前提是值、标签和触点完整。

## 表单阶段、重复行与规则各有位置

基本资料、重复场次/条目、确认提交应形成同级而明确的阶段。可用简短标题或编号；若已有阶段标题，不再另加一条重复的静态流程说明。每个重复行有稳定的可见编号和删除入口，用户能分辨正在修改哪一行。

常规输入附近只放影响当前选择的规则。另一模式的长规则在切换到该模式时展开，并保留可发现入口；提交限制与确认信息放到相应阶段。原文不能丢失，也不能将不可逆或关键限制藏在无提示的折叠区。

首次未选择的字段用可理解的提示，而不是一串横线或内部值。空结果说明可采取的下一步。错误摘要说明如何继续、能定位到对应可见输入；只有已实测保留值时才说明“已保留填写内容”。

## 错误不会破坏字段对齐

每个字段将标签、控件和下方帮助/错误作为一组，同行字段的组顶端对齐。不要用 `align-items: end` 将带错误的整组与正常组底部对齐，否则错误出现后另一输入会上移或下移。若某字段标签会换行，按内容为标签区保留一致高度或改为更合适的列布局。

重复行的错误摘要必须排除已删除/不适用的字段，并使用对应行的身份。检查“添加多行→删除中间行→触发错误→修改剩余行→提交”，以及全删后的恢复。切换模式后隐藏字段的旧错误不能继续占据摘要或夺走焦点。

## 最终比较不能只看一张漂亮截图

复核至少包含：默认与筛选列表、空结果、首次填写、普通错误、重复行错误和可用模式。先判断具体用户任务是否更清楚，再看同屏信息量；不要求所有内容硬塞进首屏。两种方案共有的问题也要修，选中较好的方案不等于它已经足够好。

## 返回时恢复任务，但重新判定当前布局

记录列表条件、来源条目、滚动和键盘焦点时，把它们与布局状态分开。一个展开区在手机由按钮控制，在桌面可能常显且没有按钮；切换宽度、方向或输入方式后，不能盲目回放旧视口的折叠布尔值。当前宽度必须满足“内容直接可用，或者有可见可用的入口”。恢复旧滚动也不能把焦点送到不可见的节点。原链接、浏览器后退和同一地址的不同来源条目分别验证。

若页面同时有折叠控件和跨页返回，至少实际走一遍：窄屏收起 → 进入详情 → 改成宽屏 → 返回并使用原控件；再反向测一次。从原页直接缩放也要可用。这是与真实页面状态相关的功能检查，不以两张固定尺寸截图代替。
