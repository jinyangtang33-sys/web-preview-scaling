# 预览差异、测量与触屏验证

用于明确的布局故障和最终风险核验；页面设计决策先按 render-quality.md 完成。

## 建立可比较的视图

1. 确认目标页面、关键区域和预期布局。优先采用用户反馈问题时的窗口尺寸、浏览器缩放和页面状态；新页面沿用设计稿或项目约定。缺少桌面基准时，可先用 1440 × 900 CSS 像素查看首屏，这个尺寸只用于测试。
2. 在独立浏览器标签页或项目已有的浏览器自动化环境中打开同一路由。保持内容、侧栏开合、滚动位置一致，等字体和图片加载后再比较。常规基准用 100% 浏览器缩放，用户报告了特定缩放时也要复现该条件。
3. 分别读取页面自身的 `window.innerWidth` 和 `window.innerHeight`。如果预览嵌在 iframe 中，在承载网页的 frame 内读取。记录 CSS 像素尺寸，截图文件的像素数、显示器分辨率和聊天面板宽度都不能代替这项测量。

先把独立浏览器设为与小窗**相同的 CSS 视口**，比较同一元素的计算字号、边界和换行；再只改变视口到交付尺寸。这样可以分开观察宿主差异和宽度变化。小窗可能已经呈现桌面布局，每次重新取数。相同视口下几何仍不同时，先核对根节点 `clientWidth`（滚动条占宽）、实际字体、内容状态和嵌入容器。预览不可访问时，给窄视口结果标注“独立浏览器模拟”。

## 采集可复查的读数

预览端用现有浏览器工具读取页面。独立端可用项目已有的测试工具，或用附带的 [measure.cjs](../scripts/measure.cjs) 在独立无头 Chromium 中批量测量。脚本适合能在干净会话里直接打开的页面；需要登录、进入弹层或切换数据时，在已有授权会话或项目的测试夹具里复现同一状态。

从已有 Playwright 或 playwright-core 的项目目录执行，脚本路径指向此 skill 目录。下例的 URL、选择器和第一个视口都应换成当前页面的实际值。使用已安装的 Chrome 时传 `--channel chrome`，使用 Playwright 配套的 Chromium 时省略该参数。

```sh
node "<skill-dir>/scripts/measure.cjs" "http://127.0.0.1:4179/#before" --viewport 971x1244 --viewport 1440x900 --selector main --selector h1 --selector .stops --channel chrome
```

动态页面可用 `--ready "CSS选择器"` 等待内容出现，`--screenshots DIR` 保存各视口的首屏 PNG。输出 JSON 包含实际视口、页面横向溢出、元素边界尺寸、字号和网格轨道。每个选择器应唯一命中关心的元素；缺失或重复时只返回匹配数量。先检查页面、元素和字体是否就绪，再比较数字。没有这些运行依赖时，可在浏览器开发者工具中读取同一组属性。

用 `--touch` 模拟触屏输入，输出会记录实际的 `hover`、`pointer` 媒体查询结果和触点数。选择器的读数还包含 `visibility`、自身及祖先合成的 `effectiveOpacity`、是否有 `display:none` 祖先。这些是定位线索，不是视觉通过证明；脚本不会自动判断遮挡、文字对比度或内容是否必须显示。

需要检查页面整体呈现时，可用 [render-inspect.cjs](../scripts/render-inspect.cjs)，其 URL、`--viewport`、`--touch`、`--channel`、`--ready` 和 `--screenshots` 参数与上例相同；不需要传元素选择器。它列出隐藏/截断候选、标题层级、操作位置和图片实际拟合尺寸。已有交互测试可复用其导出的 `inspectRenderedPage`，对具体页面状态取数。候选不是缺陷判决，应结合截图判断。

## 根据差异定位原因

- **看起来大小不同，但换行和列数相同。** 对比同一标题的计算字号、主容器的 `getBoundingClientRect().width` 和原始视口截图。如果页面几何尺寸一致，只是预览把画面缩小展示，保留页面样式。
- **两处命中了不同布局。** 把独立浏览器调到实测的预览视口，再逐渐拉宽到目标尺寸。找到换行、换列或导航折叠发生的位置，检查对应的媒体查询、容器查询和父容器可用宽度。对照设计确认窄屏与桌面的预期差异。
- **桌面比例确实失衡。** 沿异常元素向上检查尺寸来源。例如正文行长随窗口无限增长，检查内容容器的宽度约束；标题只在宽屏过大，检查字号中的 `vw`；图片被拉扁，检查宽高约束和 `object-fit`。用一处能解释现象的测量值确定修改位置。
- **内容被裁切或横向溢出。** 比较 `document.documentElement.scrollWidth` 与 `clientWidth`，再检查越界元素的边界和祖先的裁切规则。区分整页溢出与表格、轮播等组件内部预期的滚动。

## 触屏与内容可见性

涉及手机或触屏时，在目标宽度之外启用触屏模拟，记录实际 `(hover: none)` 与 `(pointer: coarse)`；只缩窄鼠标浏览器不能代表触屏操作。浏览器模拟仍需注明来源，不能冒充真实设备。

先在没有悬停、点击或聚焦卡片的初始状态检查，再通过正常滚动查看内容。用户用于识别条目、理解状态和选择操作的文字或入口，应能直接看见，或有清楚且可用的触屏替代入口。节点存在、尺寸非零、整页无溢出、点击流程成功，都不能单独证明内容可读。结合截图检查目标及祖先的 `opacity`、`visibility`、`display`、裁切和遮挡，定位仅靠 `:hover` 显示的必要内容。

同一组件在首页、结果列表和详情等被测页面复用时，分别抽查；局部样式可能只覆盖其中一处。对照鼠标悬停、触屏初始态及实际打开操作后的状态。修复后再次检查未悬停的状态，避免测试操作本身暂时显出了内容。

保留有等价入口的响应式隐藏、关闭中的菜单/弹层和可正常滚动到的内容；不要把所有隐藏节点一律显示。沿用项目现有的触屏呈现规则，修复必要内容的缺失，并复查桌面状态。把可复现的不可见、不可操作与尺寸等视觉偏好分开报告，缺少设计依据的偏好不算已证实缺陷。

## 修复与验收

在用户要求实现或修复时，优先调整造成偏差的容器、组件或断点，沿用项目已有的字号和间距规则。避免用整页 `zoom`、`transform: scale()` 或隐藏根节点横向溢出来补偿预览差异。

在目标视口和预览对应的窄视口复查同一区域；改了断点就测试临界值两侧，涉及移动端就补测项目支持的手机尺寸。检查原问题是否消失，同时确认换行、图片比例和主要操作入口符合各尺寸的设计。

交付时给出来源（实际小窗、独立浏览器或模拟）、视口、修复前后同一指标、对应 CSS 规则和观察到的效果。报告仅覆盖已测的来源和状态。若无法运行浏览器，列出静态检查发现的候选原因和待验证尺寸，将视觉验收标为待完成。

## 用示例自检

在 skill 目录运行 `python -m http.server 4179 --bind 127.0.0.1 --directory example`，两端打开同一地址，或直接打开 [示例 HTML](../example/index.html)。在同尺寸下切换“修复前 / 修复后”。顶部仪表可与脚本的独立 DOM 读数交叉核对。

示例在 1440 × 900 下，修复前 `7vw` 应得到 100.8 px 的标题，修复后应为 52 px，版心上限为 960 px；759 px 与 760 px 宽处应分别为一列和三列。即使整页横向溢出均为零，标题和版心仍可能超过设计目标。这些数值仅是示例的验收条件。

要自动核对两个版本的标题字号和断点列数，从已安装 Playwright 或 playwright-core 的项目目录运行 `node --test "<skill-dir>/tests/layout.test.cjs"`。测试直接打开示例 HTML，无需启动服务。默认使用 Playwright 配套的 Chromium；使用本机 Chrome 时，先设置环境变量 `PLAYWRIGHT_CHANNEL=chrome`（PowerShell 中运行 `$env:PLAYWRIGHT_CHANNEL = 'chrome'`）。
