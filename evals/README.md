# 诊断验证与历史实验

## 当前定位

本仓库用于网页呈现故障诊断：取数、复现、定位候选原因，以及在明确授权后验证局部修复。没有自动美观评分或通用网页优化能力声明。

当前维护范围为 scripts 中两个采集器、同状态/同视口的[诊断流程](../references/preview-diagnostics.md)、示例与浏览器回归。历史模型偏好分数不作为诊断工具的发布指标，也不能证明当前 skill 的额外收益。

## 自动检查覆盖

推送 main 或向 main 提 PR 时，CI运行14项基础浏览器检查：

- measure.cjs 的参数/选择器契约、触屏媒体特征、透明祖先和截图输出。
- render-inspect.cjs 的图片框与拟合尺寸、隐藏/截断候选和操作遮挡读数。
- 示例两组预设字号、版心和759/760px断点。
- 历史产物检查器对正确、未修复及正常隐藏/内部滚动的区分。
- [跨尺寸返回检查](check-responsive-return.cjs)在最小复现中的正常与失效情况。

另重放公开实验的补丁、预算账本及依赖指纹，防止归档失真。这些步骤不调用模型、不复做盲评、不判断美观，也不自动验证任意业务网站。

## 诊断交付条件

1. 明确页面、状态、来源、预期依据和实际CSS视口。触屏记录真实媒体查询结果；未访问的预览宿主或真机保持未验证。
2. 以可重复读数和截图解释异常。区别根溢出与组件内部滚动、正常隐藏与必要内容缺失，不把候选列表直接当缺陷清单。
3. 修复另有授权时，仅在故障范围内改动，并复测同一指标和相关操作；未改动时也可以交付“没有复现”或“证据不足”。
4. 脚本改动要通过对应测试；skill或环境变化后的历史行为结果不自动适用，缺少实测保持未验证。

目前没有新的诊断版独立行为批次或稳定版认证。现有测试只能支持上述已覆盖契约。
