# Skill 验收与发布标准

当前发布等级为实验版。示例截图、格式检查和布局 CI 提供基础证据，稳定版还需要完成以下行为验收。网页效果的增益另按[真实页面对照协议](visual-outcomes.md)验证，以相同任务下的最终页面和原有功能为对象。

最新未见项目验证：[TodoMVC 相同回复次数和时间上限](results/2026-11-05-heldout-todomvc/README.md)。两边各三次代码回复、十五分钟上限，功能均通过，盲评平均差 +1.5/24，未过预设 +2 分门槛。包括两次无效执行的记录；完整源码和截图可公开复查，未据此调整 skill。

最新记录：[真实网页效果对照](results/2026-11-04-visual-outcomes/README.md)，以两项真实前端任务比较最终页面并保留全部开发轮次。此前的[触屏可见性修订与对照复测](results/2026-11-04-touch-rerun/README.md)、[首次真实项目对照](results/2026-11-04-real-project/README.md)和[首次合成任务验收](results/2026-11-04/README.md)作为历史批次保留，不自动适用于新候选版本。

## 评测对象

每个候选版本记录 Git 提交，以及 SKILL.md、使用到的脚本与参考文档、cases.json 和全部评测页面的 SHA-256。执行环境记录操作系统、Node、浏览器和模型信息。未知配置写“未提供”，避免推定模型版本。

内容指纹按 UTF-8、换行统一为 LF 后计算，避免 Git 的 Windows 换行转换造成假失效。结果记录注明起始提交；本次新增文件通过内容指纹绑定。相关输入变化后应重新评测，历史通过结果不会自动适用于新版本。

用例及逐项验收条件见 [cases.json](cases.json)。这些是可复现的合成任务，覆盖已识别的风险。实际 Codex 预览、需要登录的业务页面和跨浏览器兼容性还需单独记录真实项目证据。

## 独立执行

1. 将每个 fixtures 子目录复制到独立临时目录。执行者只获得用户请求、该目录和必要运行工具。显式调用场景 01–06、08 再提供 skill 与测量脚本的副本。07 只提供技能名称、描述和可读取路径，观察是否按需选择。
2. 使用没有开发历史的新会话。执行者不能读取 cases.json、验收记录或其他用例的结果。保留最终回答、改动文件和浏览器原始读数。记录工具失败与重试。
3. 由维护者按 cases.json 逐项检查，重新读取修改后页面验证结果，并核对差异。每项标为 pass、fail 或 untested，附证据文件及说明。
4. 01 和 06 各用另一个新会话重复一次。对 01 和 02 各运行一次不提供 skill 的对照，使用相同请求、原始页面及工具条件。报告两边真实差异。
5. 发现失败后先保留失败记录，修复 skill 或脚本，再使用新副本复测相关场景及基础回归。候选文件发生变化后，旧记录只作为历史证据。

本地浏览器测试可使用 Playwright 或 playwright-core，并通过 file URL 打开页面。06 的浏览器不可用条件是评测约束，该场景只允许静态检查。

### 复核任务产物

从已安装 Playwright 或 playwright-core 的目录执行：

```sh
node "<repo>/evals/verify-output.cjs" 02 "<run>/project"
```

使用本机 Chrome 时设置 `PLAYWRIGHT_CHANNEL=chrome`。该脚本检查 01–05、07、08 的最终页面；它不能判断执行者是否先取证、误报来源或越过权限。06 和报告中的语义判断必须人工核查。错误退出码表示产物未满足对应条件。

08 检查触屏初始态的必要文字、透明祖先、跨区域复用，以及正常隐藏的响应式导航、关闭菜单和组件内部滚动。自动检查仍需结合截图和差异审查，不能把 DOM 尺寸、透明度或可点击状态单独当成视觉验收证明。真实项目复测应使用原始快照、相同请求与工具条件，执行者不接收漏检答案或评判标准；已用于开发反馈的项目属于回归证据，不能充当独立泛化证据。

对于会保存列表状态的页面，[跨尺寸返回检查](check-responsive-return.cjs) 可嵌入项目的 Playwright 测试。传入两端视口与项目自己的操作：打开列表、进入详情、返回、找到筛选控件和可选的展开按钮，并在 `exercise` 中实际使用控件、断言结果变化。导航回调须等待目标路由及其控件完成渲染；不要把详情中的相关列表当成已返回。以独立的触屏上下文分别运行窄→宽、宽→窄。[最小复现与测试](../tests/responsive-return.test.cjs) 覆盖“桌面按钮消失但筛选仍关闭”的失败，也检验正常常显及有展开入口的实现。这条 CI 测试验证检查器，不自动代表真实项目通过。

基础 CI 运行 `node --test tests/*.test.cjs`，覆盖测量接口（含触屏能力与透明祖先读数）、图片内容框与拟合尺寸、遮挡候选、示例字号与断点，以及产物检查器能否接受正确页面、拒绝未修复页面。诊断脚本不会返回视觉质量通过判决。**CI 不调用模型，也不自动重跑上述独立行为评测。** 发布时另按该流程执行并保存记录。

## 第一版稳定发布门槛

- 基础检查全部通过，包括 skill 格式、说明与资源链接、测量脚本契约、现有字号和断点回归。
- 八个行为场景逐项通过，01 和 06 的第二次独立执行也通过。未执行或证据缺失的项目保持 untested。
- 所有 hard_fail 为零。错误修改正确页面、掩盖溢出、编造测量或夸大验证范围均阻止发布。
- 01 和 02 的无 skill 对照已完成。如果两边效果相同，应如实说明当前评测未证明额外收益。对外宣称提升时需补充能支持该说法的结果。
- 至少一个真实项目在实际预览与独立浏览器上完成同状态、同视口对照，留存读数、修复差异或无需修改的判断及复测结果。模拟 iframe 用例覆盖的是模拟宿主。
- 宣称使用 skill 能改善网页效果时，应满足[页面效果对照门槛](visual-outcomes.md)，保留无增益与退化的历史轮次。开发反馈案例与未见过的新项目验证分开报告，模型偏好不冒充用户偏好。
- 最终提交的 CI 通过，维护者审阅结果记录并批准发布。README 的成熟度描述与验收状态一致。

这些门槛是本仓库第一版的工程验收约定。模型、skill、脚本或支持的工具环境变化时，重新执行受影响的场景。基础 CI 通过后仍需检查行为结果与真实项目证据。
