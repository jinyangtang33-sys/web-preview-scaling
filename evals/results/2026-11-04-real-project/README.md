## 实际观察

有 skill 的两次执行均发现：实际 IAB 在 1280×720 时，根节点宽度为 1265px；Playwright 默认隐藏滚动条的无头浏览器为 1280px。调整测试浏览器的滚动条条件后，两端几何一致，页面 CSS 无需补偿。维护者另用相同 HTTP 快照独立验证了这一原因。无 skill 的执行同样没有乱改全局字号，但缺少这一步受控对照。

手机搜索页的素材名称依赖悬停，窄屏常显名称规则只覆盖了首页。维护者在 390×844、`hasTouch=true`、`hover:none` 下复现：原版全部 10 张搜索卡片名称的 opacity 为 0。有 skill 的两个最终版本仍为 0；无 skill 的两个版本将已有的手机文字样式应用于其他素材卡片，复核后 10/10 可见。搜索与详情同系列卡片受到同一规则影响。这是可复查的可见性问题，功能点击测试通过并不能排除它。

三个执行版本还扩大了手机竖图：A 从约112×199px增为260×464px；B、D增为308×549px。C保留原有16:9展示框与放大入口。原版没有拉伸或裁切，图片完整放大后宽约342px。扩大详情图会把下载与收藏向下推，例如B、D的下载按钮顶部从486px移到835px。**这属于设计取舍，未计入客观缺陷修复分数。**

## 执行与复核

- A、D不加载布局/设计/验收 skill；B、C显式加载被测 skill。其余任务和工具一致，均使用新会话。
- 四轮均实际打开各自 Codex IAB 标签页，默认实测1280×720；独立浏览器覆盖1440×900与390×844。B、C另测1280×720。
- 执行者的独立Chrome HTTP被环境拒绝，改用同项目file URL，并明确记录file模式多出的下载提示。维护者另通过已获准的本地HTTP访问，对四个最终副本重跑同一组交互及几何检查。
- 维护者复核971×1244、1440×900、390×844下的首页、搜索、详情和大图，以及390触屏和739/740/741px相邻断点。四份产物主要交互通过，未观察到新增整页溢出。
- 精确模型版本、采样参数及token/费用不可得；各会话继承同一宿主配置。前三轮并行，D在A结束后启动，不能用墙钟时间宣称效率提升。
- 原项目文件的SHA-256与冻结快照一致。改动仅在隔离副本，没有应用到原项目。

## 证据和结论边界

完整工程、原始读数、执行记录、补丁、脚本及截图保存在维护者本地的 `.local-evals/2026-11-04-real-project/`，已被Git忽略；公开仓库仅保留去标识化的数值和结论。该摘要不是可由公众独立复现的开放基准。判定由开发会话复核，不是第三方盲审。

这是真实项目的现有前端原型，不代表生产后端或真实手机验收；没有测试视频完整播放、上传、下载及其他浏览器。只有一个项目、每组两次，不能推广为所有任务或模型的结论。

当前证据支持把本 skill 定位为**浏览器几何对照辅助流程**。它尚未证明能提高完整页面验收的缺陷发现能力；这次两次有 skill 执行均漏掉了一项已复现的可见性问题。稳定发布前需要针对这个缺口改进并重新测试，不能以CI通过或完成一次真实项目执行代替验收通过。
