# 真实网页效果：开发对照记录

执行日期为 2026-11-04 至 2026-11-05。前七轮未达到完整门槛；第八批确认首次通过。在素材库和摄影预约这两个开发案例上，新的两位评审四次均选择有 skill 产物，平均分差 +4.25/24，四份网页均通过独立功能复核。被测 skill 对应[候选提交 059335f](https://github.com/jinyangtang33-sys/web-preview-scaling/commit/059335f9667d9777ca5d6e0cd67477f4d96100de)。

## 输入与方法

- 素材库：真实前端快照，覆盖首页、搜索筛选、横竖图片详情、收藏及大图查看。
- 预约系统：另一真实项目的模板和静态文件，配合合成数据及固定隔离服务；覆盖列表、筛选、空结果、表单、错误恢复和日期行。没有接入生产数据库、登录、通知或审批。
- 桌面 1440×900，手机 390×844 并启用触屏模拟。相同数据、页面状态和采集脚本分别采集两组。
- 第一轮四个产物分别由新会话执行；后续保留第一轮的无 skill 产物作为固定对照，每个候选仍由新会话从原始源码开始。执行者不知道旧结果或评分答案。
- 每轮两位新的最终评审，匿名标签对换，只接收原始任务、页面和截图。六项各 0–4 分，另由独立复核检查内容及功能。最终评审不参与制作，也不读取实现报告或其他评审结果。
- 第三轮起，skill 的制作过程增加独立审查及修正，属于处理组工作流程。额外模型调用和时间没有做成本匹配，因此不宣称效率更高。
- 第五轮起，制作过程比较两份独立完整实现，再选择与修订。这是额外资源参与的工作流程测试，无 skill 对照仍为第一轮一次实现；不能将结果解释为等成本下的纯提示词效果。

完成条件始终不变：两个项目均获两位评审明确偏好有 skill 产物，平均成对总分差至少 2/24，且没有内容、功能、可见性或验证真实性的硬性退化。详见[冻结的判定规则](../../visual-outcomes.md)。

第一轮第二位评审的预约判断因任务中断没有完成，未填补或推定结果。五轮中各自四个产物的独立内容与功能复核均通过，但没有达到整体视觉优势门槛。

第一轮过于突出图片尺寸，使列表名称和操作更难连续扫读。第二轮改善了密度，但手机图片留白、纵向动作与说明的组织仍有代价。第三轮通过独立审查补了交互细节，却仍弱于对照的筛选分组、可见动作文字和桌面表单层级。这些结果促使下一版先完成页面结构，再使用尺寸诊断，并把原始页面与候选一起交给制作阶段的复核。

第四轮素材库的密度和图片动作有局部收益，但仍有重复收藏、手机筛选排列及图片与动作位置的取舍。预约系统的首次选择提示、错误返回说明和桌面表单概览仍弱于对照。第五轮因此按任务加载诊断文档，并在制作阶段实际比较两种完整方案，减少围绕一份布局不断修补的偏向。

第五轮素材库获得两位评审的小幅偏好，依据是有文字且不遮图的操作、大图查看入口及桌面浏览密度；预约仍因宽屏表单过长、阶段分组和错误时输入错位而落后。第六轮加入具体布局与状态模式，并向制作阶段的比较评审提供这些规则，让它检查两份方案共同存在的弱点。最终匿名评审始终不读取 skill 或这些规则。

第六轮在相同的 390×844 首屏中，无 skill / 有 skill 的素材首页分别显示 0 / 4 个完整条目名称；预约列表可看全 1 / 2 条记录。桌面两版都能看全 8 条预约。有 skill 的素材页在桌面也更早呈现照片，但手机竖图初览大小有取舍。预约评分分歧来自首次填写：对照版的必填提示、模式选择顺序和错误定位更清楚。独立功能复核还发现有 skill 的素材页从手机详情切换到桌面再返回时，会把桌面分类/筛选控件留在关闭状态且不显示展开入口；原始页面和固定对照没有该问题。即使素材视觉获两票也不可抵消这项退化。以上读数是开发案例中的具体结果，不是新的通过标准。

第七轮增加了按需读取的首次填写与纠错参考，并要求按当前视口恢复跨页状态。两个项目从原始源码重新制作，仍与原来的固定对照比较。390×844 下，素材首页无需滚动就能读到的条目名称从 0 个变为 4 个；预约首屏能看全的记录从 1 条变为 3 条，第一条记录的上边缘从 473 px 提前到 246 px。桌面两版都能看全 8 条预约，首个开始日期输入框从 y=731 提前到 y=438。完整分类在有 skill 版需要展开；预约宽屏并排也使长用途输入变窄。这些取舍和收益一起报告。

第七轮已在真实素材页走过“窄屏进详情 → 横屏返回 → 实际选择图片类型”及反向路径，原始页、固定对照和有 skill 版均可用。预约页验证了模式切换、删除中间行、错误定位和两类演示提交。制作阶段实测的收益还包括为释放范围提供有效的默认开始时间，并在换范围时保留仍合法的人工选择；没有修改业务校验。手机模拟不等于真机。采集器最初只会展开原生折叠区，加入对有明确控制关系的按钮的支持后，两组用同一脚本重新采集，保留首次失败日志。

第七轮四票均偏好有 skill，两个有 skill 产物均过硬门槛。但无 skill 预约页报错后切换模式或删除报错行，摘要仍链接到已隐藏字段；两种目标尺寸均可复现，对照组未过。另设第八批确认，先锁定只修该对照错误、保留其他三个产物不变，再盲评，不覆盖第七轮的失败记录。

第八批无 skill 对照只改了一份 JavaScript 文件，后台、数据、模板及样式均未改。其 18 张预约标准截图和第七轮逐像素一致。另三份前端的全部文件（40、41、15 个）逐字节不变；重新截图时有三个状态的局部像素不同，分别是两份素材页的桌面灯箱和有 skill 预约页桌面筛选按钮所在区域，其余图像一致。确认不等于又生成了两次成功的有 skill 网页。两位新的匿名评审仍偏好有 skill 的素材与预约：手机上可直接比较更多实际条目，桌面可同时核对场次和提交条件；对照版的分类概览、竖图缩略图和部分错误说明各有优势。

## 证据与复现范围

[脱敏逐项结果与候选指纹](observations.json)包含每轮六维分数、偏好、硬性结果、缺失记录和 SHA-256。候选同时记录本地原始字节指纹与 LF 统一换行指纹；后者用于核对 Git 中的文本。固定对照的源码逐文件核对，未通过重新生成选择更弱对照。

同视口补测记录在 `matched_viewport_observations`（有采集的轮次）。素材首页数的是边框完整落在首屏内的**条目名称**，预约列表数的是完整的**记录行**。详情页测下载与收藏控件，表单测首个起始日期字段；位置以从视口顶部起算的 CSS 像素表示。这些计数用来解释具体差别，不参与盲评打分，也不代替内容遮挡与可操作性复核。

完整原始项目、匿名截图、执行记录、交互测试、源码差异、失败重试和冻结清单在维护者的本地私有归档中保留，未发布私人项目源码或素材。因此公开摘要可核对数值与版本，不能独立复现整套私有项目实验。预约服务依赖、脚本及合成数据与归档一起保存；服务仅监听本机回环地址。

实际 Codex 预览由维护者单独补测，并与相同 CSS 视口的独立 Chrome 比较。这是统一的补充证据，不冒充各执行者自行完成的预览检查。浏览器触屏模拟不是手机真机；没有验证 Safari、生产后端或完整辅助技术体验。

确认批次核查两浏览器中 6 个匹配状态：实际预览视口为 1280×720，页面可用宽度 1265 px，同视口独立 Chrome 为 1280 px；对应标题字号相同，两边均无整页横向溢出。功能复核覆盖 100 个页面状态，含换尺寸后返回并继续筛选、模式切换后的错误链接去留、全删后添加和纠正后提交。素材详情的放大用于查看细节，不宣称每张图都可按原始像素 1:1 查看。第七轮另以新会话复测合成触屏用例 08，独立检查通过；这不是最新版本八个合成用例全部通过的声明。

第五轮另以新会话执行了 06 静态诊断、07 单一文案、08 触屏内容可见性，均通过对应复核：06 明确区分推导和实测，07 只替换指定文字，08 只扩展一处触屏选择器并保留正常隐藏与内部滚动。它们不是网页质量分数，也不代表八个行为场景和重复执行要求已经在最新候选全部完成。整页截图改变触屏媒体特征的环境问题及重试已保留；最终统一视觉采集使用固定视口截图，并核对截图前后的输入特征。

## 结论边界

两个项目已参与多轮反馈，属于开发案例。反复调整后得到的结果不能用作未见项目上的泛化结论，也不构成统计显著性或任意任务必然更好的保证。所有轮次保留，最终模型偏好与用户实际偏好分开。基础 CI 和行为回归另行记录，不替代网页效果门槛；当前仍为实验版。
