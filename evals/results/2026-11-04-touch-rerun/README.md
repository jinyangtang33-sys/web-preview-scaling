# 触屏与内容可见性：修订后的对照复测

新版 skill 在同一个真实项目上两次都发现并修复了上一轮漏掉的触屏文字隐藏；本轮无 skill 的两次执行也都修复了。**已补回已知漏检，尚未证明比不使用 skill 的验收效果更好。** 当前仍为实验版。

| 条件 | 修复必要文字隐藏 | 解释 |
|---|---:|---|
| 上一轮旧 skill | 0/2 | 历史记录，环境与本轮不完全相同 |
| 本轮新版 skill | 2/2 | 两次均只修正共享卡片文字样式 |
| 本轮无 skill | 2/2 | 两次均修复同一问题，另调整手机竖图大小 |

这些是四次独立执行的计数，不是总体成功率。竖图原本保持比例并有放大入口，改变显示大小涉及信息优先级与滚动距离，本轮仍按预先约定作为设计取舍，不计入客观缺陷修复分数。

## 本轮改动

- skill 要求记录真实输入媒体能力，在未悬停、未聚焦、未点击的初始状态检查必要内容，并抽查组件在首页、结果列表与详情中的复用。
- 将节点存在、尺寸非零、点击成功与实际可读区分开；检查自身及祖先透明度、可见性、裁切和遮挡，同时保留有替代入口的响应式隐藏、关闭菜单及正常内部滚动。
- `measure.cjs --touch` 提供触屏模拟及输入媒体读数，并输出 `visibility`、`opacity`、`effectiveOpacity`、`ancestorDisplayNone`。这些读数是诊断线索，不能自动证明视觉验收通过。
- 新增公开课程目录用例 08，以及触屏测量、修复正例和误显示隐藏内容/破坏内部滚动的反例。基础 CI 为 10/10 通过；CI 不调用模型。

## 对照方法与复核

沿用[上一轮](../2026-11-04-real-project/README.md)的真实素材管理前端原始快照，40 个文件哈希逐一一致，没有植入新故障。四个新会话获得相同请求、代码和独立浏览器工具；A、D 获得冻结的新版 skill 与脚本，B、C 不获得 skill。执行者看不到旧结果、协议和评判标准。前三次并行，D 在 B 完成后启动；不据此比较耗时或费用。模型为相同继承配置，精确版本和采样参数未提供。

Windows 账户问题导致四个新会话均无法启动实际 Codex 预览；执行者均把该范围标为未验证。本轮独立 Chrome 可通过提升权限访问 HTTP，而上一轮曾使用 file 回退。因此旧版与新版之间的差异不能严格归因于 skill 修改。

维护者对四份最终副本统一复核，未采用执行者自行声称的检查数量作为比较分数：

- **触屏初始态**：390×844 与 1440×900 均实读 `hover:none`、`pointer:coarse`。原始搜索页为 0/10、详情关联区为 0/4；四份结果分别恢复为 10/10、4/4，首页 9/9 保持可见。复核截图、文字样式与源码差异，桌面 1440×900 的悬停呈现及关闭弹层保持正常。
- **功能**：每份副本在 971×1244、1440×900、390×844 各走搜索、筛选、打开详情、收藏及放大关闭五组流程，12 个采集状态均无整页横向溢出，无 JavaScript 异常。另检查触屏放大/关闭。
- **实际预览补测**：维护者已有的 IAB 会话可用，统一在实际 1280×720 下检查首页、搜索、详情、放大、关闭五个状态；独立 Chrome 在同视口保留滚动条后，采样几何差在 0.1 CSS px 内。默认无头滚动条隐藏造成的 15px 宽度差单独记录。此项是维护者补测，不计作四名执行者自行完成。

基础测试初版曾错误假定默认触点数为零；实际主机报告 10，但 `hover:none` 和 `pointer:coarse` 均为 false，已改为按实际能力判断。产物检查器的 file URL 等待规则和维护者脚本的跨路由鼠标位置残留也已修正；保留初次失败记录后重跑，没有将测试脚本问题算作网站或 skill 缺陷。
