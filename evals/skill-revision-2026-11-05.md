# TodoMVC 后的定向精简

## 证据与解释

上一候选的未见项目配对平均仅 +1.5/24，未达 +2 门槛。两边相同脚本均为30/30，补充操作均8/8；无 skill 执行者也能完成字号、触屏动作、长文和键盘入口等常规改善。两位评审的偏好主要来自筛选顺序、持续字段标签和编辑后果提示，而非整体布局能力差异。

这不证明某一句指导导致了某项得分。候选的四份设计文档有大量通用排版建议、具体列数模板和默认双完整方案流程；前者与模型已有能力重叠，后者在三次代码回复的约束下不可执行。旧执行器还把所有 Markdown 参考一次性装入，未实现原本的按需阅读。较大的上下文和实际耗时差是观察值，文档负担造成效果有限只是工作假设。

## 修订及保留

- 四份文档由8505字符减为2264字符，按LF统一换行统计，约减少73.4%。入口、任务路径、布局边界、表单边界分工，删除重复排版讲解及强制列数示例。
- 不默认增加完整独立实现与模型审查；用户要求或预算能解决重要不确定性时才追加。
- 保留少数有可见依据的决策：常用选择易返回、必要输入有持续语义、关键后果在决策处解释；优先解决一两个任务阻碍。
- 保留跨视口返回、触屏非悬停信息、错误链接适用性和诚实验证边界。测量脚本与预览诊断未改动，仍按问题加载。

TodoMVC 不再修改、重评或作为新候选的通过测试。新项目在新候选冻结后执行；同模型/推理、各三次补丁回复、零模型工具、900秒总上限及300秒每次上限。仍用两个新的匿名评审、六维24分、均偏好有 skill 且平均差至少2、无功能退化的门槛。

新执行器仅注入入口与当前模式的参考，不再无条件塞入全部文档；具体载入清单事前记录。此处同时改变内容与加载方式，不能把未来结果单独归因于“字符更少”。协议、预算、全部结果与无效执行都保留，不按结果反复调新项目。

## 冻结后的新项目结果

新 Markdown Editor 两位盲评为19/17、18/17，平均+1.5/24；两边各48项主功能检查通过。更大手机写作区和明确阅读切换形成小幅偏好，但另一方案的同屏输入/预览也有实际价值。精简没有在本次验证中建立明确优势；不同项目之间相同的分差不构成新版与旧版效果相同的证明。

较可信的解释仍是：通用页面优化与基础模型能力重叠，本候选主要改善局部任务组织。尚不能区分具体指导、加载方式、随机生成和模型评审波动的贡献。后续不应根据本例继续堆规则、降低门槛或宣称精简提高了效率；若要归因，需另行预先设计同项目多版本、重复运行的试验。本次没有开展该试验。
