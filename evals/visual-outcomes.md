# 网页实际效果的对照验收

目标是使用户使用 skill 后得到更好的网页呈现与使用体验。基础测量、自动测试和检查项数量不替代这一目标。之前的素材库案例保留为开发回归，新增真实预约系统模板作为不同类型的前端任务；后者使用合成数据和隔离适配服务，不代表生产业务验收。

## 冻结输入

在执行前保存相同项目快照、用户请求、工具环境、候选 skill 指纹、分组以及以下判定规则。执行者使用新会话，不获得旧结论、目标缺陷或评判答案。两组均可使用浏览器、编辑与迭代；只有处理组获得被测 skill 及其脚本。保留失败、平局、环境故障和所有修订轮次。

同一个项目使用相同页面、数据、视口、输入能力及操作状态采集最终结果。桌面为 1440×900，手机为 390×844 触屏模拟。若预览工具不可用，两组如实注明，维护者的补测单列，不伪装为执行者自行完成。

## 页面质量

两名独立评审只获得任务和匿名网页/截图，不获得分组、skill、执行报告、其他评审的分数或开发者偏好。顺序交换，先记录判断再揭示条件。分别评估：

1. 条目和信息是否容易辨认、比较和扫读。
2. 层级、分组、字号与间距是否清楚。
3. 主体内容的呈现与操作是否支持页面任务。
4. 手机布局是否连贯，信息和操作是否可用。
5. 桌面空间利用与布局是否合理。
6. 跨页面与状态是否一致，是否有无关装饰或不必要复杂度。

每项 0–4：0 无法使用；1 有明显任务障碍；2 可用但存在明显问题；3 清楚连贯；4 有具体证据支持的出色呈现。每个分数必须说明页面和状态中的可见依据，不能因改变更多代码或采用某种流行风格加分。24 分总分仅用于本批次成对比较，不是客观美观指数，也不换算成提升百分比。

## 必须保留的能力

由独立复核检查两组同等流程：素材库的搜索、类型/方向筛选、详情、收藏与放大关闭；预约列表的筛选和空结果，表单的错误恢复、日期行增删、常规/剩余模式及本地校验提交。

丢失或虚构内容、删掉功能、新增重要内容不可见或裁切、图片比例错误、整页溢出、编造验证结果均不能用视觉分数抵消。正常组件内部滚动与有替代入口的响应式隐藏应保留。自动判定与截图、源码差异共同复核，选择器变化本身不是功能失败。

## 本轮完成条件

两个真实项目任务中，两名评审均基于具体可见理由偏好有 skill 的产物；成对总分差的平均值至少为 2/24；没有上述硬性退化。未满足时保留结果，按暴露的问题继续开发并以新副本执行，不能修改原评分让本轮通过。

这是工程迭代的工作门槛，不是统计显著性结论，也不能保证任意项目、模型或未来执行都优于无 skill。模型评审的偏好与最终用户偏好分开报告；交付实际页面和同状态图片供用户复核。曾用于改进的任务标为开发案例，后续泛化验证使用未参与改进的新任务。

## 开发反馈后的迭代

后续轮次可在执行前明确保留原有无 skill 产物作为固定基线，并核对逐文件指纹；新候选仍从相同原始源码开始，执行者不获得旧产物、评分或修复答案。使用新的匿名评审，保留相同维度和完成门槛。这类固定基线比较记录的是开发任务上的改善，不是每轮重新随机执行的实验；参与反馈的项目均标为开发案例。所有轮次、方法调整和失败结果一并报告，不只展示最后一次结果。

如果候选 skill 引入实现阶段的独立审查，该审查属于被测工作流程，单独记录其反馈、修正与额外执行成本。最终成对比较必须使用另一组未参与制作的评审，不能让实现阶段的评审给自己的建议验收打分，也不能把追加模型调用解释为效率提升。

第七轮的视觉比较通过，但固定无 skill 对照未过硬门槛；该轮仍记为整批失败。另设对照修复确认：在修订前锁定只允许普通维护者修复对照中这一处失效错误链接，不给维护者 skill；两个有 skill 产物及素材无 skill 对照逐文件不变。逐张对比修复前后预约对照的标准截图，由两名新的盲评员重新评价全部页面，独立复测全部硬门槛，仍用相同判定条件。该批检验对照变强后优势是否仍在，不是第七轮重打分，也不是又一次从头使用 skill。

第五轮起，候选还在制作阶段比较两份独立完整实现，再选择与修订；无 skill 固定对照仍为第一轮的一次实现。这里测试的是包含额外资源的完整工作流程，不能据此声称在相同调用次数或耗时下，单独增加这段说明就能提高效果。内部方案及被放弃的选择同样保留，最终盲评只评冻结的最终产物。

若要进一步判断收益能否迁移，先冻结候选提交，再选择没有用于制定规则的新项目。提前固定任务、判断门槛与重复次数；两组使用同一模型、工具、方案数、审查机会和时间预算，记录实际成本。所有项目一起报告，包括失败与平局。该验证与本次开发案例分开，不以继续调整已见页面替代。
